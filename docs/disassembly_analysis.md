# Анализ ассемблерного кода (x86-64, AT&T)

## 1. Исследуемый фрагмент

```asm
        movl    $0, -4(%rbp)        # (1)
        movl    $1, -8(%rbp)        # (2)
        jmp     .L2                 # (3)
.L3:
        movl    -8(%rbp), %eax      # (4)
        addl    %eax, -4(%rbp)      # (5)
        addl    $1, -8(%rbp)        # (6)
.L2:
        cmpl    $10, -8(%rbp)       # (7)
        jle     .L3                 # (8)
        movl    -4(%rbp), %eax      # (9)
```

## 2. Соответствие переменных

В синтаксисе AT&T порядок операндов: `источник, приёмник`. Локальные переменные лежат в стековом кадре относительно `%rbp`; каждая занимает 4 байта (суффикс `l` = long, 32 бита).

| Место | Роль | Имя в коде высокого уровня |
|---|---|---|
| `-4(%rbp)` | аккумулятор (накапливает сумму) | `total` / `sum` |
| `-8(%rbp)` | счётчик цикла | `i` |
| `%eax` | временный регистр; в конце — регистр возвращаемого значения | — |

Обратите внимание: счётчик и аккумулятор здесь живут **в памяти (на стеке)**, а не в регистрах. Это типично для кода, скомпилированного без оптимизаций (`-O0`). Регистр `%eax` служит промежуточным буфером и в конце хранит результат, так как по соглашению System V AMD64 целочисленное значение возвращается через `%eax`.

## 3. Пошаговая трассировка

| Инструкция | Действие |
|---|---|
| (1) `movl $0, -4(%rbp)` | `total = 0` |
| (2) `movl $1, -8(%rbp)` | `i = 1` |
| (3) `jmp .L2` | безусловный переход к проверке условия (цикл с предусловием) |
| (7) `.L2: cmpl $10, -8(%rbp)` | вычисляет `i - 10` и выставляет флаги |
| (8) `jle .L3` | переход, если `i <= 10` (знаковое «меньше или равно») |
| (4) `.L3: movl -8(%rbp), %eax` | `eax = i` |
| (5) `addl %eax, -4(%rbp)` | `total += eax`, то есть `total += i` |
| (6) `addl $1, -8(%rbp)` | `i += 1` |
| (9) `movl -4(%rbp), %eax` | после выхода из цикла `eax = total` (возвращаемое значение) |

Управляющая структура: `jmp` на проверку → тело цикла (`.L3`) → проверка (`.L2`) → условный переход назад. Это стандартная компиляция цикла `for`/`while` в GCC.

## 4. Восстановленная логика

Код считает **сумму целых чисел от 1 до 10 включительно** и возвращает результат.

### Эквивалент на C

```c
int sum_to_10(void) {
    int total = 0;
    for (int i = 1; i <= 10; i++) {
        total += i;
    }
    return total;
}
```

### Эквивалент на Python

```python
def sum_to_10():
    total = 0
    i = 1
    while i <= 10:
        total += i
        i += 1
    return total
```

Более идиоматичная запись: `return sum(range(1, 11))`.

## 5. Проверка результата

Значения по итерациям:

| Итерация | `i` (на входе) | `total` (после) |
|---|---|---|
| 1 | 1 | 1 |
| 2 | 2 | 3 |
| 3 | 3 | 6 |
| 4 | 4 | 10 |
| 5 | 5 | 15 |
| 6 | 6 | 21 |
| 7 | 7 | 28 |
| 8 | 8 | 36 |
| 9 | 9 | 45 |
| 10 | 10 | 55 |

После десятой итерации `i = 11`, условие `11 <= 10` ложно, цикл завершается. Итог: `total = 55 = 10·11/2`, функция возвращает **55**.

## 6. Замечания

- Условие `jle` включает границу: при `jl` цикл шёл бы до 9 и сумма была бы 45. Именно `jle` даёт «от 1 до 10 включительно».
- Фрагмент не содержит пролога/эпилога (`push %rbp`, `mov %rsp, %rbp`, `ret`), то есть это только тело функции.
- Начальный `jmp .L2` делает проверку условия до первого выполнения тела (`while`-семантика); если бы начальное значение `i` было больше 10, тело не выполнилось бы ни разу.
