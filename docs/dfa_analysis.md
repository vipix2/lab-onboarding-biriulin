# Анализ потоков данных (DFA): `process_transaction`

## 1. Исследуемый код (с нумерацией строк)

```python
 1  def process_transaction(user_id, amount, db_connection):
 2      log_entry = "Start processing"
 3
 4      if amount > 0:
 5          status = "approved"
 6          balance = get_balance(user_id)
 7          new_balance = balance - amount
 8          update_balance(user_id, new_balance)
 9
10      log_entry = "Transaction finished with status: " + status
11
12      file = open("audit_log.txt", "w")
13      file.write(log_entry)
14
15      return status
```

## 2. Цепочки Def-Use

| Переменная | Def (определения) | Use (использования) |
|---|---|---|
| `user_id` | строка 1 (параметр функции) | строка 6 (`get_balance(user_id)`), строка 8 (`update_balance(user_id, ...)`) |
| `amount` | строка 1 (параметр функции) | строка 4 (условие `amount > 0`), строка 7 (`balance - amount`) |
| `db_connection` | строка 1 (параметр функции) | **нет использований** |
| `log_entry` | строка 2 (`"Start processing"`), строка 10 (`"Transaction finished..."`) | строка 13 (`file.write(log_entry)`); значение из строки 2 не используется нигде |
| `status` | строка 5 (`status = "approved"`) — только внутри ветки `if` | строка 10 (конкатенация), строка 15 (`return status`) |
| `balance` | строка 6 (`balance = get_balance(user_id)`) | строка 7 (`balance - amount`) |
| `new_balance` | строка 7 (`new_balance = balance - amount`) | строка 8 (`update_balance(user_id, new_balance)`) |
| `file` | строка 12 (`file = open(...)`) | строка 13 (`file.write(...)`) |

### Пары Def-Use по каждой переменной

- `user_id`: (1 → 6), (1 → 8)
- `amount`: (1 → 4), (1 → 7)
- `db_connection`: пар нет
- `log_entry`: (2 → ∅) — определение «убивается» на строке 10; (10 → 13)
- `status`: (5 → 10), (5 → 15) — только при `amount > 0`; при `amount <= 0` определения нет вовсе
- `balance`: (6 → 7)
- `new_balance`: (7 → 8)
- `file`: (12 → 13); освобождающего использования (`close`) нет

## 3. Дефекты, выявленные методами DFA

### Дефект 1. Использование неинициализированной переменной (`status`)

- **Где:** строка 10 (`"..." + status`), а также строка 15 (`return status`).
- **Условие возникновения:** `amount <= 0` (ноль или отрицательное значение). Тогда ветка `if` на строке 4 не выполняется, определение `status` (строка 5) не достигается, и на строке 10 переменная читается без значения.
- **Результат:** `UnboundLocalError: local variable 'status' referenced before assignment`.
- **Почему не видит линтер:** синтаксически код корректен; проблему видно только по графу потока управления: существует путь `1 → 2 → 4 → 10`, на котором нет ни одного `def status`.
- **Исправление:** задать значение по умолчанию до `if` (например, `status = "declined"`) или добавить ветку `else`.

### Дефект 2. Мёртвое присваивание (Dead Store) — `log_entry`

- **Где:** строка 2 (`log_entry = "Start processing"`).
- **Объяснение:** значение определяется на строке 2, но на всех путях выполнения переопределяется на строке 10 до первого чтения (строка 13). Определение из строки 2 не имеет ни одного use — оно «мёртвое».
- **Следствие:** запись «Start processing» никогда не попадает в аудит-лог, хотя, вероятно, предполагалось логировать начало обработки. Это указывает на логическую ошибку (нужно `+=` или отдельная запись), а не только на лишнюю строку.
- **Дополнительно (по тому же принципу):** параметр `db_connection` определён на строке 1 и нигде не используется — «неиспользуемый параметр». Функции `get_balance` и `update_balance` вызываются без соединения с БД, то есть, вероятно, работают с глобальным состоянием или соединение просто забыто.
- **Исправление:** удалить присваивание либо накапливать лог: `log_entry += "\nTransaction finished ..."`.

### Дефект 3. Утечка ресурса (Resource Leak) — `file`

- **Где:** строка 12 (`file = open("audit_log.txt", "w")`).
- **Объяснение:** файловый дескриптор захватывается на строке 12, использован на строке 13, но на пути до `return` (строка 15) нет вызова `file.close()` и не используется менеджер контекста. Определение `file` не имеет «освобождающего» use.
- **Последствия:**
  - дескриптор остаётся открытым до сборки мусора;
  - данные могут остаться в буфере и не попасть на диск (потеря записи аудита);
  - при исключении на строке 13 (например, нет места на диске) ресурс не освобождается тоже;
  - при большом числе транзакций возможно исчерпание лимита открытых файлов.
- **Исправление:**
  ```python
  with open("audit_log.txt", "a") as file:
      file.write(log_entry + "\n")
  ```

## 4. Сопутствующие замечания (не из DFA, но стоит отметить)

- Режим `"w"` при каждом вызове **перезаписывает** `audit_log.txt` — история аудита теряется. Для аудита нужен режим `"a"`.
- Нет проверки, что `balance >= amount`; `new_balance` может стать отрицательным.
- Если `update_balance` выбросит исключение, статус `"approved"` уже определён, но запись в лог не будет выполнена — нужна обработка ошибок (`try/finally`).
